## What changed since 2026.11.013-nightly

### Multiplayer

- **Orders reach the other players sooner.** The game sends its orders in a packet every 100 ms (a beat). Each beat now leaves as soon as it is written instead of waiting up to 25 ms, and arrived a median 24 ms sooner on every network we measured, with the same amount of data.
- **Large orders no longer freeze the game.** A big order, such as a 44 KB one in our tests, used to stall a multiplayer game for about 21 seconds. The game now sends up to 64 KB at a time instead of 2 KB, and resends lost packets sooner. This only changes how your own game sends, so it helps in games with players on the original game too.
- **A faster link between two players on this engine** in native network mode (`/nativenet`): their games carry the game's data on a new "game channel" that repeats lost data quickly and stays encrypted. The network panel and the tray say "game channel" for such players. Players on other builds are connected as before.
- **Live game viewing and the FAF client link are steadier.** Watching a game live no longer goes out of step after a long script message, and the game no longer loses its link to the FAF client when the client sends it a long message (#479, by M3RT1N99).
- None of this changes the simulation: replays play back exactly as before.

### Graphics

- **Detailed water on Direct3D 12 and Vulkan** at high graphics quality: rolling waves along the map's wind, a glittering sun path, sparkles near the camera, moving light patterns in clear shallow water, and a soft shoreline with a thin line of foam. Each map keeps its own water colours. It costs about 10 % more GPU time than FAF's water (measured on Seton's Clutch) and can be turned off in Options > Video > Detailed water.

### Fixes

- Zooming with the mouse wheel no longer makes the cursor flicker to the Windows arrow.
- An open log window no longer uses a whole CPU core. At the main menu with a large log window the game used 117 % of a core before and about 28 % now (24 % with no log window).
- Clicking two neighbouring map names quickly now shows the second map instead of picking it: a double click now has to land within a few pixels, as in Windows, not 32 pixels apart (#478).
- After a desync pauses a replay, the pause button now shows the replay as paused and resumes it on the first click (#477).

### For testers and developers

- New network settings and defaults, with the measurements behind them in `docs/NETWORK_MEASUREMENTS.md` and every setting in `docs/SWITCHES.md`: `net_FlushBeats` (on), `net_MaxSendRate` and `net_MaxBacklog` (65536), `net_FastRetransmit` (on), `net_GameChannel` (on, native mode only) and `net_LagAuto` (off; it sets the order delay from the measured round trip, but in test games it pulled two players' delays apart). To go back to the original game's sending, type `/con net_MaxSendRate=2048;net_MaxBacklog=2048;net_FastRetransmit=0;net_FlushBeats=0` in the console.
- `ren_WaterDetail` switches the detailed water from the console.
- A benchmark for beat delivery over simulated networks (`faf_netbench`, `tools/netbench`) and tests for the game channel and the GPGNet stream.
- Code cleanup to newer C++ forms, with no change in behaviour.
- The nightly replay check and the nightly releases are paused; releases are now made by hand.
