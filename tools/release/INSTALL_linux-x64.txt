The engine's native Linux build (no Wine). Needs Linux x64 with glibc 2.34 or newer (Ubuntu 22.04,
Debian 12, Mint 21, RHEL 9 and their successors; Fedora, Arch, SteamOS 3, openSUSE Tumbleweed), a Vulkan
driver (Mesa or NVIDIA), FAF's game data and Forged Alliance itself.
It plays with players on the rebuilt engine (Windows or Linux) over its own network links; it can't join
games of the original ForgedAlliance.exe.

What is in this package
  ForgedAlliance                 the engine (Vulkan)
  faf-launch                     starts it with your Forged Alliance install and FAF's game data
  libdxcompiler.so, libdxil.so   shader compiler; must stay next to ForgedAlliance
  libfaf-glibc-compat.so         a few C library functions the shader compiler needs on glibc 2.34-2.37
  fafengine/lua/...              the engine's own Lua hook files; must sit in a folder named fafengine
                                 next to ForgedAlliance (the engine mounts it at /fafengine)

Install
  Extract this package into a folder of its own, keeping fafengine as is:
    mkdir -p ~/faf-engine && tar -xzf faf-engine-<version>-linux-x64.tar.gz -C ~/faf-engine

Run, from that folder:
  ./faf-launch /nobugreport /log ~/faf-engine.log /windowed 1280 800

faf-launch finds Forged Alliance (FAF's fa_path.lua, then Steam's library folders) and FAF's data folder
(FAF's client.prefs, then ~/.faforever), which FAF's client fills when it first starts a game or replay.
`./faf-launch --show` prints what it found; --fa DIR and --faf-data DIR name the folders when it
doesn't find them. It writes its own fa_path.lua into ~/.local/share/faf-re/init and leaves FAF's files
alone.

From a FAF client that starts the rebuilt engine (the test build of FAForever/downlords-faf-client#3590),
put ForgedAlliance in the client's bin folder as ForgedAlliance.exe, with the three .so files and
fafengine next to it.

A crash prints its stack to the terminal (or the desktop session's log); please attach it together with
the log file from /log.
