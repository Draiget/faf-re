Windows · x64 · FAF client

Run the rebuilt engine
with Forged Alliance Forever

Build faf-re, connect it to your existing FAF installation, and launch games through the FAF client. These steps are based on a successful Windows setup.

1. Install the prerequisites

  • Your own working copy of Supreme Commander: Forged Alliance and the FAF client. Launch a normal FAF game once so the client downloads its game files.
  • Visual Studio 2022 Build Tools with Desktop development with C++, a Windows SDK, C++ CMake tools for Windows, and C++ ATL for x86 and x64.
  • LLVM, including clang-cl and lld-link, installed in C:\Program Files\LLVM. The maintainer’s current guide specifies any version requirements.
  • Git for Windows.
This builds the engine only. You still need the original game’s assets and FAF’s downloaded game data.

2. Download and build the engine

Open PowerShell in the folder where you want the source code, then run:

git clone --recursive https://github.com/Draiget/faf-re.git
cd faf-re

Select Visual Studio’s bundled CMake and Ninja. This path assumes the standard Build Tools 2022 installation:

$cmakeTools = "C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\Common7\IDE\CommonExtensions\Microsoft\CMake"
$env:PATH = "$cmakeTools\CMake\bin;$cmakeTools\Ninja;$env:PATH"

If you use Visual Studio Community, Professional, or Enterprise, use its corresponding CMake installation path, or put CMake 3.25+ and Ninja on PATH.

Build x64 Release:

.\build.ps1 -NoCopy -Jobs 8

Dependencies download and patch automatically. Use a smaller job count on PCs with limited memory. A successful build produces:

build\clang-x64-release\src\main_x64.exe

3. Prepare the FAF launch folder

From the repository folder, run:

.\build.ps1 -NoBuild
Copy-Item "C:\ProgramData\FAForever\bin\*.lua" `
          "C:\ProgramData\FAForever\bin_x64\" -Force

The script stages the executable, debug symbols, engine hooks, and DXC DLLs. The second command copies FAF’s initialization scripts.

These steps assume FAF’s default data folder: C:\ProgramData\FAForever. For another location, pass -FafDir "D:\Your\FAForever" to the build script and adjust all paths below. If staging reports access denied, run the staging commands in an administrator PowerShell.

4. Configure the FAF client

Open ☰ → Settings → Forged Alliance Forever. Scroll down to the executable settings.

Command Line Format for Executable

"C:\ProgramData\FAForever\bin_x64\main_x64.exe" /con lua_AllowPrecompiledChunks=1;ren_GpuSelectBrackets=0

Execution directory

C:\ProgramData\FAForever\bin_x64
Game LocationKeep this pointing to the original Steam/game installation.
Relative Game PathsLeave disabled.
Maps and Mods LocationKeep your existing FAF vault location.
Compiled-Lua mods: lua_AllowPrecompiledChunks=1 enables mods such as EconomyMiddle and RFA. It also permits compiled Lua from other loaded maps and mods. If you do not need compiled-Lua compatibility, remove lua_AllowPrecompiledChunks=1; while keeping the selection-bracket setting.

Restore the selected-unit rings / brackets

If the selection indicator around a unit is missing on the battlefield, set ren_GpuSelectBrackets=0 as shown in the command above. This disables GPU-instanced selection brackets and uses the engine’s fallback drawing path.

For an existing setup, replace Command Line Format for Executable with the full command above. Both settings belong in one /con argument, separated by a semicolon.

If you also use a standalone desktop shortcut, right-click it → Properties and set Target to:

"C:\ProgramData\FAForever\bin_x64\main_x64.exe" /init init_faf.lua /nobugreport /con lua_AllowPrecompiledChunks=1;ren_GpuSelectBrackets=0

Set the shortcut’s Start in field to C:\ProgramData\FAForever\bin_x64. Close and relaunch the game, then select a unit to check that its battlefield selection indicator is visible. This setting affects selection rings / brackets, not the unit portrait in the bottom panel.

Close Settings. Changes apply to the next game launched; an already running game keeps its existing engine. Exit the FAF client normally when finished so it can save its preferences.

5. Verify the setup

  1. Host or join a private, unranked test game through the FAF client.
  2. Open Task Manager → Details. The game process should be main_x64.exe.
  3. Check that the lobby connects, your mods load, and the game runs without desyncs.

The client supplies the lobby, player, replay, and network arguments. A standalone desktop shortcut does not connect you to a FAF lobby.

The maintainer reports multiplayer compatibility with the original engine. This remains an independent engine build; successful launch alone does not verify multiplayer compatibility for every game or mod.

Updates, troubleshooting & restore

Refresh FAF’s launch scripts

After FAF updates its initialization scripts, copy the current versions again:

Copy-Item "C:\ProgramData\FAForever\bin\*.lua" `
          "C:\ProgramData\FAForever\bin_x64\" -Force

Common problems

  • Missing atlbase.h: install the Visual Studio C++ ATL component, then rebuild.
  • CMake or Ninja not found: check the bundled-tools path in step 2 and the installed CMake tools component.
  • Game fails to start: check the executable and working-folder paths, copied Lua scripts, and the newest game log in the FAF client’s log folder (available from its ☰ menu).
  • Mods appear but fail: inspect the game log for compiled-Lua rejections or other mod errors.

Return to the normal FAF engine

Clear Command Line Format for Executable and Execution directory in FAF Settings. The next launch uses the normal executable. No replacement of FAF’s original executable is needed.
