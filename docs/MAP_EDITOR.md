# Map editor

`FafEditor_x64.exe` (x64) / `FafEditor.exe` (x86) is the map editor: its own program, built from the same engine code as the game. It draws through Direct3D 12 or Vulkan only, and plays maps inside its own window.

*Snapshot: 09/11/2026. The editor's window, panels and Play. Opening and saving maps, the 3D edit view and the tools come next.*

## Building and running

```powershell
.\build.ps1 -Editor        # builds only the editor's target, copies FafEditor_x64.exe (+ .pdb) to bin_x64
.\build.ps1 -Editor -Configuration Debug
cd C:\ProgramData\FAForever\bin_x64
.\FafEditor_x64.exe /init init_faf.lua /log C:\ProgramData\FAForever\logs\FafEditor_x64.log
```

In VS Code, the Run view has "Editor (x64, Debug)" and "Editor (x64, Release)": F5 builds the editor's target of `clang-x64-debug` or `clang-x64-release`, copies it to `bin_x64` and starts it under the debugger with `/init init_local_development.lua` (the Lua of the FA checkout, as the engine's own F5 entries use). "Editor (x64, no build)" starts what is already there. Only running editors are stopped before the copy; the game is left alone. The `.vscode` files are local (not in git).

`-Editor` never replaces the game's `main_x64.exe`, its headless or the DXC DLLs in the run folder (the editor carries its own DXC); a Profile build is copied as `FafEditor_x64_profile.exe`, and `-Out` also copies it to `out\<arch>\`. The editor reads the game data the way the game does: `/init <file>` names the init file (FAF's `init_faf.lua`), else `SupComDataPath.lua` next to the exe.

## Play

The toolbar over the panels starts with **Play** (F5), then New, Open, Save, Save as, Undo and Redo, Grid, Snap and the grid's step (Grid draws the cell edges on the ground around the cursor; Snap puts markers and props placed or dragged in a cell's middle, while mass and hydrocarbon points always sit on half units as the game's saves place them; `/grid`, `/snap`, `/gridstep <n>` for test runs), and names the open map at its right ("edited" while it has unsaved changes). Pick a map in the Map panel (each map by its title, then its folder name; type to filter; double-click opens it for editing) or in Play > Map, and press **Play** or F5. The map loads and plays inside the editor's view, between the panels, with the game's own interface. **Stop** or F5 returns to the editor. So does the game's own way out of a session: its menu's exit, quitting from the score screen, and "Exit to Windows", which stops the play instead of closing the editor. View > Panels while playing (on by default) hides the panels during play when turned off, so the game takes the whole window. The window's title says what plays.

The Map panel sets the play up, the way FAF's `/map` quick start does (`SinglePlayerLaunch.lua`) but with these choices:

- **Solo** (default) or **Against AI** with one of the game's AI types for every other army. Solo is the faster start: with no AI there is no AI map analysis (SCMP_009, second play: 2.3 s to the game solo, 4.5 s against "rush").
- **Faction**: random or one of the game's factions.
- **Fog**: fog of war ("explored") or none. The sim fixes fog when the game starts, so it applies from the next Play.
- **Keep this setup for this map**: on, the map keeps its own setup, saved at each Play; off, it plays with the setup of the last Play on any map. Picking a map takes its own setup or the last one. Kept in `%LOCALAPPDATA%\FAForever\Editor\play_setups.ini` by map folder name without its `.vNNNN` version, AI and faction by their keys. Test runs from the command line read it but don't write it.
- **See the whole map**, during play: the view switches to an observer's (no fog, every army) and back to your army. Editor plays have cheats on for this, without changing the `debug.enable_debug_facilities` preference the game reads.

Campaign maps go through FAF's own campaign setup. No replay is written.

How fast a play starts:

- The game's rules (every unit, projectile and effect blueprint, about 1.5 s to build for FAF) are built on a thread of their own when the editor starts, for the mods a skirmish uses (`RULE_PrepareKept`), and each play's rules are kept for the next one (`RULE_SetKeepBetweenSessions`). A Play pressed before they are ready waits for them. The game builds them for every session.
- Loading shows one line of text in the view ("Loading Seton's Clutch ...") instead of the game's faction movie, "IN TRANSIT" screen and loading tips, and the game's panels come in as soon as the map is ready instead of after the "IN TRANSIT" picture fades (`InstallLoadingView`, through `moho::gUIBeforeStartGameUI`).
- Solo, a Play 5 s after the editor starts reaches the game in about 2.3 s on SCMP_009 and 2.7 s on Alpha 7 Quarantine (SCMP_021, 40 km); later plays in 1.0-1.3 s and 1.6-2.0 s (Direct3D 12, Vulkan). On SCMP_021 two engine changes do it: the 3584 building skirts its start flattens update the terrain normal map one tile at a time for all of them (`IWldTerrainRes::NotifyMapChanges`, 30 ms where one update per skirt took 1.6 to 3.3 s), and a whole-map normal-map rebuild after the map changed is encoded on 4 threads as the loader's (0.4 s, from 1.6 s).

| Switch | Effect |
|---|---|
| `/d3d12` | Direct3D 12 only |
| `/vulkan` | Vulkan only |
| (neither) | Direct3D 12, then Vulkan; if neither starts, the editor says so and exits |
| `/log <file>` | The engine log, as in the game; the Log panel shows it too |
| `/logtimes <file>` | Also writes every log line with its time in seconds since the editor started (the Log panel's "Times" box shows the same), for timing where a play's start goes |
| `/play <map>` | Plays that map (its folder or scenario name, e.g. `SCMP_009`) once the editor is up |
| `/playseconds <s>` | With `/play`: stops after s seconds of play |
| `/playcycles <n>` | With `/play`: plays and stops n times |
| `/playafter <s>` | With `/play`: waits s seconds after the editor is up before the first play (timing a first play as a user would start it) |
| `/playquit` | With `/play`: closes the editor after the last one (test runs) |
| `/playai <key>` | With `/play`: against that AI (`rush`, `easy`, ...) instead of solo |
| `/memtrace` | Records every heap block's call stack (slow) and, after each play, logs the call sites of what the play before it left alive, the largest first. Without it the log still gets, two seconds after each play, the process's private memory split by heap, thread stacks and direct allocations, what grew since the last play, the Lua range's use by size class, and the engine types whose live count changed |
| `/open <map folder>` | Opens that map for editing at start (the folder name without `_scenario.lua`, any case) |
| `/openall` | Opens every map in `/maps` in turn, logs each one and a summary of those that did not open fully, then closes the editor (test runs) |
| `/playsetups <file>` | Reads and writes the remembered play setups in that file instead of `play_setups.ini` (test runs) |
| `/playwholemap` | With `/play` and `/playseconds`: switches to the whole map when play starts and back halfway (test runs) |
| `/playexitapp` | With `/play` and `/playseconds`: ends each play the way the game's "Exit to Windows" does (`ExitApplication()`), which the editor turns into a Stop (test runs) |
| `/d3d12debug`, `/vulkandebug` | The API's debug or validation layer, as in the game ([Renderer backends](RENDERER_BACKENDS.md)) |

`/play` takes several maps separated by commas; the runs take them in turn.

The window is always one maximized, movable, resizable window with a menu bar (File, View, Play), whatever the game's display options say; the game's own display option doesn't change it either. The panel layout is kept in `%LOCALAPPDATA%\FAForever\Editor\layout.ini`; View > Reset layout restores the default.

**Open for editing** (Map panel) opens the picked map into the editor's document on a thread of its own: the `.scmap` as the game loads it, `_scenario.lua` and `_save.lua`, each in the editor's own Lua state, apart from any play. The Info panel (View > Info; View > Reset layout docks it beside the Map panel) shows what was read: size, height field, water, terrain shader, the ten texture layers, props, decals, markers by type, armies and the map's files. Between plays the game's view shows the opened map (terrain, texture layers, decals, water) through the game's own renderer, as the original editor did: the editor puts its map in the renderer's map (`REN_SetWldMap`) with a world view and a camera of its own (`view/EdMapScene.cpp`), and takes them away before a play's session takes over. Camera: middle mouse button drag orbits, Shift + middle drag or right drag pans (the ground follows the cursor), WASD or the arrow keys move (Shift faster), the wheel zooms toward the point under the cursor without changing the camera's tilt, Home frames the whole map. The map's props are drawn as mesh instances from the blueprints of the rules the editor keeps for its next play (`RULE_PeekKept`), once those are built after startup.

**Terrain brush:** with the Terrain tool, the left mouse button held over the opened map paints heights with the panel's mode (Raise, Lower, Smooth, Flatten to the height under the stroke's first point, Set height to the panel's height, Noise, Terrace to the nearest step, Plane through three points Ctrl+clicked on the terrain, Stamp: a height image added over the brush's square once per click, white adding the stamp height times strength), radius, strength, falloff and symmetry (`tools/EdHeightBrush.cpp`). Limits leave alone the vertices outside a height range or steeper than a slope (judged at each symmetry group's first vertex, so copies stay identical). `/brush <mode>` and `/stamp <file>` set the mode and stamp image for test runs. Symmetry is exact: each group of mirrored samples gets one new height, computed from its first member, written to all of them, so mirrored halves stay identical and a stroke on a mirror line applies once (GoogleTest `faf_editor_brush_tests`). N-way turns (2 to 16 copies, the panel offers 3 to 8) can't be exact, as their copies fall between vertices: the first sector (from the map's centre towards +x, turning towards +z) is painted, and every other vertex the brush covers, plus 2 vertices past its edge, takes the height at its point turned back into the first sector, read between vertices; 4 turns are exact. The diagonal and turn modes paint without symmetry on a map that isn't square. The symmetry's mirror lines are drawn along the ground with a translucent wall standing on each (the turn centre as a vertical axis, the sectors' edges for N-way turns), and the brush shows as rings on the terrain at every copy (white at the cursor, orange at the mirrored ones; the inner ring is where the falloff starts), drawn through the renderer's editor hook (`ED_SetHook`). Edit > Undo and Redo, Ctrl+Z and Ctrl+Y (or Ctrl+Shift+Z) in the view or the panels, take back whole strokes, byte for byte (`undo/EdHeightHistory.cpp`: the 32 x 32 tiles a stroke touched, before and after; 256 MB at most, the oldest strokes go first).

**Texture layers** (Tools panel, Texture, Layers; `tools/EdTextureLibrary.cpp`): the map's ten slots (lower, strata 1 to 8, upper), each with a thumbnail of its albedo texture, its name and its size in game units (a drag sets it; the normal map keeps its ratio to the albedo). Clicking a thumbnail opens the texture browser: every `.dds` under `/env/<biome>/layers/` the game data has, grouped by biome folder, searchable, as thumbnails (64 x 64, decoded a few a frame through the engine's image codec); picking one sets the slot's albedo and, when a `_normals.dds` lies beside it, its normal map; Empty clears a stratum. The terrain loads the new texture at once (`StratumMaterial::SetSizeTo`) and Save writes it. Slot changes undo and redo with the strokes (a size drag is one step). `/layer <slot>,<albedo path>[,<size>]` and `/browse <slot>` do the same for test runs.

**Texture painting** (Tools panel, Texture; `tools/EdMaskBrush.cpp`): the paint list shows the map's strata 1 to 8 by texture name (the lower layer lies under all; the upper one is blended by its own alpha). Paint raises the chosen stratum's weight, Erase lowers it, Smooth evens it out; "Lower the layers above" makes Paint lower the strata blended over the chosen one by as much, so it shows. The brush's radius, strength, falloff, symmetry and limits are the terrain brush's; symmetry is exact on the masks' texels as on heights (N-way turns paint the first sector and copy the nearest turned-back texel). Weights move by whole steps with a per-step dither, so weak strokes still reach full. Rules set a stratum to full where the ground lies in a height range and/or slope range, over the whole map, in order (Apply rules to whole map, one undo step). When the Texture tool first acts on a map, the terrain enters edit mode (`EnterEditMode`, as the original editor did: the masks become writable textures) and the masks are read into the editor (`GetStratumMask`); a stroke writes back only what it changed (`UpdateStratumMask`). Strokes undo and redo with the height strokes in one order. The paint list shows each stratum's share of the map, and "Show the layer's weight" colours the paint layer green over the ground where it lies (blocks of 4 x 4 mask texels, rebuilt after each change; `/layerweight` with `/masklayer` for test runs); under it, Clear empties the chosen stratum's mask, Import reads it from a grey image (PNG, BMP, TIFF, RAW or R16, resampled to the mask's size) and Export writes it (16-bit grey PNG, RAW or R16, the weight times 257), each one undo step. With the Texture tool the symmetry check compares the masks' texels (all eight layers at once) and the copy of the source part copies texels. The shader picker under the slots lists every technique of the game's `terrain` effect that it marks composite (33 with FAF's data: `TTerrain`, `TTerrainXP`, `Terrain000` ... `Terrain301`), the shaders a map may name; a change is one undo step, and the engine checks the name again before it draws (the shader's extra slots for the 100- and 200-series are not edited yet). `/shader <name>` changes it for test runs. `/masklayer <1-8>` and `/maskrule <layer>,<low>,<high>` set the layer and apply a height rule for test runs; `/roundtrip` now also compares the eight masks texel for texel.

**Symmetry on open** (`DetectSymmetry`): maps don't store the symmetry they were made with, so while a map loads its heights are compared with their copies under each mode on a 128 x 128 grid of points (within half a game unit); of the modes where at least 97% match, the one with the most copies is set in the Tools panel, which names it with its match share. A flat map fits every mode and gets none. Over the 63 retail and test maps 24 get a mode (Seton's Clutch a half turn, Drake's Ravine both axes).

**Symmetry check** (Tools panel, Terrain, under Symmetry; `tools/EdSymmetryCheck.cpp`): Check compares every vertex with its copies under the chosen symmetry and marks the differing ones as red blocks on the terrain (Show differences), with a count and the largest difference; it is kept up to date after strokes, undo and redo. N-way turns compare a vertex with the height at its point turned back into the first sector and count differences above a quarter unit. "Copy the source part to the other copies" makes the heights symmetric from the part nearest the map's top-left corner (the first sector for turns), as one undo step. Texture masks and objects are not checked yet. `/symcheck <mode>[x<turns>][:repair]` with `/open <map>` runs the check (mode: the panel's symmetry, 0 None to 9 N-way) and the copy on the drawn map (GoogleTest `faf_editor_brush_tests`: a planted one-vertex difference is found and repaired in every mode).

**Height field import and export** (Tools panel, Terrain, Height field; `tools/EdHeightFile.cpp`): Import reads `.png`, `.bmp` or `.tif` through the Windows imaging component as 16-bit grey (8-bit images spread over 16 bits), or `.raw` / `.r16` (World Machine) as 16-bit little-endian words, square or of the map's size; it is resampled to the map's size and is one undo step. Export writes `.png` (16-bit grey), `.raw` or `.r16`, at the map's size or 257 to 4097 wide (a rectangular map keeps its proportions). Heights are times the panel's height scale both ways; a word is 1/128 of a game unit, as in the map file. `/heightexport <file>` and `/heightimport <file>` with `/open <map>` do the same from the command line, and `/heightdialog` opens the import dialog (GoogleTest `faf_editor_brush_tests`: every format reads back what it wrote).

**New map** (File > New map, Ctrl+N; `doc/EdNewMap.cpp`): a title, the folder (FAF's `name.v0001`, from the title until edited), skirmish or campaign, 5 to 81 km, 1 to 16 players, the ground's height and an optional sea with its level (deep and abyss 2.5 and 15 below). The document's worker makes the engine's empty map (`CWldMap::MapNew`, 0x00890D40: the default layers, cleared masks) at that height and sea, and writes `<vault>/maps/<folder>/` with the `.scmap` (a 256 x 256 preview, ground green or sea blue, the start positions as dots), `_scenario.lua`, `_save.lua` (start markers `ARMY_1`... in a ring at 35% of the size, the first at the top; one army entry each plus `ARMY_17` and `NEUTRAL_CIVILIAN`) and `_script.lua`. The folder is then mounted at `/maps/<folder>` (`CVFSImpl::MountDirectoryLate`, an engine addition), listed in the Map panel and opened. `/newmap <folder>[,<size 0-4>,<players>,<height>,<sea level or 0>]` does the same from the command line. The sea's water map starts empty (flat shading) until the water tools fill it.

**Props** (Tools panel, Props): a searchable list of every prop blueprint the game's rules have (`GetPropBlueprints`), the chosen one's reclaim mass and energy, scale and LODs under the list, and in Single mode the prop itself under the cursor with its symmetric copies (drawn by the mesh renderer, at the turn the click will use: a random turn is drawn before the click), Single (one at a click), Scatter (props a second at random points inside the brush while the button is held) and Erase (those inside the brush; Shift+click erases in any mode), random turn, the brush's radius and symmetry: each prop gets its symmetric copies, each copy turned as the symmetry carries the cursor's heading. **Select tool**: a click picks the nearest prop (Ctrl adds), a drag moves the selection over the ground, Q and E turn it by 15 degrees, Delete or Edit > Delete selection removes it; selected props are ringed in yellow. Every prop edit is one undo step (the whole prop list before and after; the newest 200 are kept). A new or turned prop is saved from a record of its own floats (position, rotation matrix, scale 1) and takes the transform the engine's `CWldProps::Load` reads back from them, so a save and a read give it back bit for bit; a moved prop keeps its rotation floats as read. `/proptool <mode>,<blueprint>`, `/tool <index>` and `/roundtripframes <n>` (the frames `/roundtrip` and `/saveas` wait) serve test runs.

**`_save.lua` and `_script.lua`** (`doc/EdSaveFile.cpp`): the editor keeps both files' text. The master chain's markers and the areas are parsed out of the save (each a name and its properties as written, so properties the editor has no use for survive); writing gives the text back unchanged, or with only a changed block (markers, areas) written anew in the game's layout. All 63 maps of the game parse, each with as many markers as its Lua gives. Save writes the two files beside a vault map when they changed; Save as writes the edited ones into the new folder.

**Decals** (Tools panel, Decals; `tools/EdDecals.cpp`, `tools/EdDecalShape.cpp`): the map's decals are the terrain's decal manager's (the game's own `CDecalManager`), so they draw as the game draws them and save with the terrain. Place mode: a browser of every texture under `/env/*/decals/` (thumbnails on a checkerboard, filtered by name and by type: albedo, normal maps, glow, the type taken from the file's name), a size along and across the heading, a turn (or a random one) and a fade distance (0: the decal works one out from its size, as the game's `AddDecals` does); a click places the decal centred on the cursor with its symmetric copies, turned with the symmetry, and the outline of the decal to come follows the cursor. A decal's position is its corner, not its middle (`CWldTerrainDecal::ComputeCorner`, 0x0089D9C0), so the editor places the corner half of each side back from the click. Select mode: a click picks the topmost decal (the last drawn), Ctrl adds, a drag moves the selection live, Shift+click or Delete removes. Each edit is one undo step (a snapshot of every decal's saved fields; undo makes the missing ones again with their index and destroys the extra ones). On opening, the log names the decals by type and the first one's fields. `/decaltool <texture>[,select]` for test runs. An albedo texture with a `_spec` next to it gets it as the decal's second texture ("With its spec map", on by default), as the game's maps keep them: SCMP_009 has 1,003 normal-map decals with one texture, 949 albedo decals with one and 284 with their `_spec` second. Thumbnails keep the decal's alpha. Path mode: clicks lay the points of a uniform Catmull-Rom curve (through every point); decals follow it end to end, each its length along the curve and its width across, turned with it, the next starting length x (1 - overlap) further on; the view shows the curve to the cursor and the decals to come for every symmetric copy; Enter or Place lays them as one undo step, Backspace drops the last point, Escape clears. In Select mode the move gizmo stands at the selected decals' middle and moves them along an axis or freely.

**Units** (`doc/EdUnits.cpp`): each army's `Units` group in `_save.lua` (groups nested in `INITIAL`, units with type, orders, platoon, Position, Orientation) is read into groups and units and written back as the game's saves write it (the source's line ends; six decimals, a half rounded away from zero as the game's writer did). With `FAF_RETAIL_MAPS` set to the game's maps folder, GoogleTest round-trips all 380 armies of the retail saves (21,971 units) byte for byte. The view draws them with their blueprint's mesh and scale, turned as `CreateUnitHPR` turns Orientation's heading, pitch and roll (`BuildRotationMatrixFromEulerHPR`, then the canonical row converter): SCMP_001's 774. The Units tool (U) picks an army (players and extra armies) and a unit type from the rules (id and name, searchable); Place puts the unit in the army's INITIAL group with its symmetric copies, named UNIT_n after the highest in the map; a player army's copy goes to the army whose start position is nearest its start's copy (SCMP_009's half turn: ARMY_1's to ARMY_2), an army without a start keeps its copies. Select picks, drags live or with the move gizmo, and deletes; each edit is one undo step with the save data. `/unittool <type>,<army>[,select]` for test runs.

**Water** (Tools panel, Water; `doc/EdWater.h`): the map's sea as the `.scmap` keeps it: on or off, the level, the deep and abyss levels (a warning when they aren't below each other), the water's colour, lerp, refraction, fresnel and reflections, the sun on the water, and the four normal maps' repeat and movement; the textures' names are shown. A change is on the map at once (the water map rebuilt when a level changes), a drag is one undo step, and the terrain's own save writes it. `/waterset <on>,<level>,<deep>,<abyss>` for test runs. Water bodies at their own levels wait for `feat/water-levels`.

**Check** (View > Check; `tools/EdChecks.cpp`): the start positions and the mass and hydrocarbon points: off the map or the playable area (error), a start under the sea (warning), a resource under it (note: naval maps have them), without a marker of its type within 2 units of each symmetric copy under the Tools panel's symmetry (warning, naming how far the nearest is), and two resources whose 2 x 2 extractors would overlap (error). The results list by marker (full text on hover); a click selects the marker and moves the camera there; the view pins each finding in its colour. On SCMP_009 under its half turn: 112 warnings, every start and resource 5 to 11 units off its exact partner, as a hand-made map is. `/check` runs it for test runs. Not yet: script errors, pathing, the script panel.

**Writing `_save.lua`**: a changed block (markers, areas, armies) keeps each entry's text: unchanged entries as read with the banners before them, a changed entry's changed values replaced in place, new entries in the game's layout and the file's line ends; a deleted entry takes its banner with it. A copy of SCMP_009 with two placed units differs from the original by those 16 added lines only.

**Info and Markers panels** (`ui/EdInfoPanels.cpp`): the Info panel shows the open map's title, where it comes from, its kind as chips (size in km, type, players, water level, the symmetry found from its heights), the description, the props, decals, markers and armies as cards, the terrain shader and each texture layer with its thumbnail and a readable name ("Evergreen2 · evgrass005"), the armies (extra armies dimmer), the markers by group, and the files (full path on hover). The Markers panel lists the markers as a tree: start positions, resources, AI markers, path nodes and other, each by type with its colour and count, each marker with its position; a filter matches names and types. A click selects the marker in the view and brings up the Markers tool to edit it (Ctrl toggles it in the selection; a click on a type selects all of its markers), a double-click moves the camera to it, and a type's eye hides it in the view (not drawn, not picked).

**Markers** (Tools panel, Markers; `tools/EdMarkers.cpp`): the master chain's markers drawn in the view (with the Markers tool all of them, path nodes with their links; otherwise the start positions and resources), each as a diamond in its own colour with a post. A palette of 20 types by group (resources, starts, AI, path nodes, other) with the properties the retail maps' saves give each; a click on the ground places one with its symmetric copies, named as the saves name them (`Mass 03`, `ARMY_9`, `LandPN04`); a click on a marker selects it (Ctrl adds), a drag moves the selection over the ground, Shift+click or Delete removes. The selected marker's name and every property are editable as the save writes them (a rename follows into the path nodes' links). Each edit is one undo step. A start position is an army: placing `ARMY_n` adds it to `_scenario.lua`'s team list and an entry to `_save.lua`'s Armies (no units, as the game's saves write one), deleting or renaming it follows; new start names skip every army the scenario lists, extra armies included. The panel's Armies section lists the FFA team's armies as the lobby's slots, in order, with up and down buttons, and edits the extra armies (`customprops.ExtraArmies`). Teams aren't edited: the game needs one team named FFA with every player army (`SinglePlayerLaunch.lua` VerifyScenarioConfiguration: "scenarios require all teams be set up as FFA"; the lobby and `maputil.lua` GetStartPositions read the first or the FFA team only), and players choose teams in the lobby; a scenario with other teams gets a warning and "Make one FFA team". The scenario's text is kept and written like the save's and the script's. Path nodes: with "Connect path nodes" on (or Ctrl+Shift+click without it), a click on a node links it to the selected nodes of its graph, both ways as the saves keep `adjacentTo`, or unlinks them, and selects it; placing a node links it to the selected one, so clicks lay a path. Under symmetry each copy links to the matching copy, and the selected copies of one node count once (the one nearest the clicked node pairs with it). Land and water nodes never link; deleting a node drops the links naming it; links touching the selection are drawn bright. Mass and hydrocarbon markers draw the splat the game gives them (ScenarioUtilities.lua `CreateResources`: `mass_marker.dds` 2 x 2, `hydrocarbon_marker.dds` 6 x 6), draped over the ground and depth-tested; they are drawn from the markers each frame, so a dragged marker's splat moves with it. The deposit props the game adds at the same time are not drawn yet. `/markertool <type>` (with `/connectnodes` for the connect mode) for test runs. `/framemarker <name>[@distance]` moves the camera to a marker. **Move gizmo:** selected markers (Markers tool), props (Select tool) and decals (Decals tool, Select mode) get arrows along X (red), Y (green, up) and Z (blue) and a square in their middle; dragging an arrow moves along it by the cursor's move projected on the arrow on screen, the square moves freely over the ground. With the toolbar's "On ground" (on by default) X, Z and free moves keep objects on the terrain, off they keep their height; the Y arrow lifts them; nothing goes below the ground. Snap applies to X, Z and free moves. Each drag is one undo step. `/uiclicks "x,y;dx,y"` feeds clicks to the panels (in their pixels, `d` for a double-click) through ImGui's input queue, one every half second from frame 300; posted window messages can't, as ImGui's Win32 backend takes the real cursor's position while the window has focus.

**Playable area (map border)** (Tools panel, Markers, Playable area): FAF has no map setting for it: a map's `_script.lua` calls `ScenarioFramework.SetPlayableArea('AREA_1', false)` in OnPopulate, with the area a rectangle of `_save.lua` (FAF's function rounds each edge down to a multiple of 4). The editor reads the area the script names, shows its border on the ground in amber and the ground outside under a dark veil, as the game darkens it; "The map has a playable area" adds one a tenth of the map in from each side (area `AREA_1` and the script's call, with the ScenarioFramework import when missing) or removes the call; the four edges are typed or, with the Markers tool, dragged in the view on the 4-unit grid. Each change is one undo step. A map saved with an area plays with it (the game logs `SetPlayableArea after round : 128, 128 896, 896`). `/playablearea x0,z0,x1,z1` (or `none`) for test runs.

**Saving** (`doc/EdMapFile.cpp`, `doc/EdDocument.cpp`):

- **File > Save** (Ctrl+S) writes the opened map's `.scmap` over its file, only when that file is in the vault (`<vault>/maps/...`): maps inside the game's archives or folders have no file of their own to save over and are saved as a new map folder instead. The first save over a file copies the old `.scmap` to `<folder>/.editor_backup/<date-time>/`.
- **File > Save as new map folder...** asks for a folder name (the next version, `seton.v0002` after `seton.v0001`, is offered) and writes `<vault>/maps/<folder>`: every file of the map's folder, those named after the map renamed to the folder's name without its version, the `.lua` files' paths into the old folder pointed into the new one, and the edited `.scmap`. The game lists it from its next start.
- The vault is FAF's (`Documents/My Games/Gas Powered Games/Supreme Commander Forged Alliance`), or `/vault <folder>` on the command line.
- What is written: the file header, the preview image as read (byte for byte), the terrain as the game's own writer saves it (version 60: heights, the ten texture layers, water, decals, masks and the rest), then the props. A prop the editor didn't move keeps its record byte for byte; a moved one is written from its position and rotation with scale 1, which the game ignores. The masks are written with the classic DDS header (`ImageCodec::PreferOwnDds`): the game's Direct3D 9 decoder doesn't read the newer DX10 header. The normal map and the water maps are rebuilt from the terrain, so their bytes differ from the original file's.
- `/roundtrip <folder>` (with `/openall` or alone: every map; with `/open <map>`: the drawn map) saves each map under `<folder>`, reads it back, compares heights, water, shader, layers, props and decals, saves again and compares bytes, then closes. All 63 maps of the game come back with the same data, and a second save is byte-identical to the first. `/saveas <folder>` with `/open <map>` saves the drawn map as that new folder and closes.

The Tools panel is laid out as the plan's mockup: a strip of tool icons and the chosen tool's settings (brush modes, size, strength, falloff, the symmetry modes with their diagrams). The settings are kept but act on a map only from the tool stages of the plan.

## How it is built

- **Target:** `src/editor/CMakeLists.txt` adds `faf_editor`, which links the engine's object library `faf_engine` whole, as the engine tests do, so the engine's objects are linked in the game's order. The game's `WinMain` is one of them, so the editor starts at its own `main()` (`/ENTRY:mainCRTStartup`). It carries the game's window resources and manifest and the DXC DLLs as the game does.
- **The game inside:** the editor's app (`EdApp.cpp`) holds the game's own `CScApp` and runs the game's loop (`WIN_AppExecute`), with what the game's `WinMain` sets up around it (the crash report's die handler, the accessibility hotkeys turned off and restored). The window, device, user interface, sound and world sessions are the game's, unchanged. Engine additions in `CScApp`, unused by the game: `moho::gAppRenderers` (Direct3D 12 and Vulkan only, no Direct3D 9/10 fallback), `moho::gAppWindowed` (one normal window; `SC_PrimaryAdapter` leaves it alone) and `moho::gAppBeforeDeviceCreate` (the editor's second head). The game's first-frame start (main menu or command-line session) is skipped; sessions start from Play.
- **Two heads:** the device has the game's head 0 on the game's viewport, which the editor keeps over the middle of its dock layout, and a head 1 on the editor's own child window under it, for the panels. The game draws only head 0 (its viewport was made for one head); the editor draws head 1 each frame, and the game's paint presents both. When the layout or the window changes, the viewport is moved and both heads are resized (`CD3DDevice::InitContext`). The game's interface lays itself out in the viewport and takes its input there, as in the game.
- **Panels:** [Dear ImGui](https://github.com/ocornut/imgui) 1.92.4, docking branch, pinned in `cmake/FafDependencies.cmake` and built by `cmake/deps/imgui`, drawn by `ui/EdImGuiRenderer.cpp` on gal's GPU programs (`gpg/gal/GpuDriven.h`): one HLSL source DXC builds for both APIs. Its input is the panels' window's; F5 is the editor's in either window.
- **Play** (`EdPlay.cpp`): the editor's Lua launcher builds the session info as FAF's quick start does and calls `LaunchSinglePlayerSession`; `WLD_Teardown` ends the session, before the game's frame would go on to its main menu. A Lua request to quit during play (`ExitApplication`) ends the session, not the editor.
- **Older renderers:** their DLLs are delay-loaded (`d3d9.dll`, `d3dx9_43.dll`, `d3d10.dll`, `d3d11.dll`), so the editor starts without the June 2010 DirectX runtime and never loads Direct3D 9. Direct3D 11 still loads when Direct3D 12 or Vulkan decode a texture: they do it on a private WARP device ([Renderer backends](RENDERER_BACKENDS.md)).

## Known issues

- Each Play still keeps about 1.2 MB of private memory after it ends (SCMP_009, 20 plays): the heap's caches (0.2-0.8 MB a play, textures and file lookups) and about 0.6 MB of the Lua range, mostly the editor's UI state growing slowly. Freed before: a sync packet's shared references (the sim's height field, 4 MB), the world meshes the game UI never destroys (13 a play), the cursor each UI state switch made (2 a play), and about 6 MB a play in the Lua range (freed large blocks were never merged, and a thread could take every free small block of a size).
- A popup of the panels that reaches over the game's view (a combo's list) is hidden behind it, as the view is its own window. Modal dialogs (New map, Save as, the texture browser) show: while one is open the view's window region is empty.
